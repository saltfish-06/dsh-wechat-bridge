# 排错

照症状查。每条都对应一个真实踩过的坑。

---

## 机器人不说话

**先看三件事**：

```powershell
# 1) 适配器活着吗、微信登录了吗
Invoke-RestMethod http://127.0.0.1:8765/status
```

- 连不上 → 虚拟机没开 / 适配器没起 / 端口转发没配。看第 2、3 节。
- 连上了但 `"ready": false` → 微信停在登录页。去虚拟机里扫码（或点「登录」+ 手机确认）。
  **扫完不用重启任何东西**，适配器 20 秒内自己接管。

```powershell
# 2) 主机桥接在跑吗
Get-Process | Where-Object { $_.Path -like "*你的目录*" }
```
没有就 `start.bat`。

**然后看日志**：主机 `logs\bridge-YYYYMMDD.log`，虚拟机 `C:\wxbridge\adapter.log`。

日志里出现 `收到（不在白名单，忽略）[昵称 / wxid_xxx]` → 把那个 `wxid_xxx`
加进 `config.json` 的 `allow` 数组，重启桥接。

## 适配器连不上

### 检查虚拟机在跑

```powershell
VBoxManage list runningvms
```
没有就 `VBoxManage startvm "虚拟机名" --type headless`。

### 检查端口转发

```powershell
VBoxManage showvminfo "虚拟机名" --machinereadable | Select-String Forwarding
```
应该有一行 `adapter,tcp,127.0.0.1,8765,,8765`。没有就加：

```powershell
VBoxManage controlvm "虚拟机名" natpf1 "adapter,tcp,127.0.0.1,8765,,8765"
```

### 检查适配器进程

```powershell
VBoxManage guestcontrol "虚拟机名" run --exe "C:\Windows\System32\cmd.exe" `
  --username <用户> --password <密码> --timeout 30000 `
  -- cmd.exe /c "cd /d C:\wxbridge && type adapter.log"
```

日志最后几行说"微信停在登录页"→ 去扫码。
日志说 `PermissionError: [WinError 5] ... wechatauto_logs` →
你是在只读目录（比如 `System32`）里启动它的。先 `cd` 到可写目录。

## 微信起不来

| 症状 | 原因 | 怎么办 |
|---|---|---|
| 双击没反应，进程一闪就没 | 工作目录不对 | 必须先 `cd` 到微信安装目录再启动 |
| 闪退，日志里什么都没有 | 缺 VC++ 运行库 | 装 `vc_redist.x64.exe` |
| 每次重启都要求重新登录 | 腾讯的行为 | 点「登录」+ 手机确认，或者扫码。**别硬重置虚拟机**（等于拔电源，一定会要求重新登录） |
| 登录了但读不到消息 | 版本升级导致密钥读取失效 | 升级 `wechatauto-replica`，或等适配 |

## 机器人突然全哑，报 `already owned by an active write handle`

Agent 上次调用超时了。`subprocess.run` 超时**只杀父进程**，Agent 派生的
node 子进程活得好好的，一直攥着会话的写句柄。

**本项目的桥接已经修了这个**（用 `Popen` + `taskkill /F /T` 杀整棵树）。
如果你还在用老代码，或者看到这个错：

```powershell
# 找出僵尸
Get-Process -Name "DeepSeek Harness" | Sort-Object StartTime |
  Format-Table Id, StartTime, @{n='MB';e={[int]($_.WorkingSet64/1MB)}}
# 杀掉最早那个（GUI 进程别杀，看启动时间区分）
Stop-Process -Id <pid> -Force
```

## 收到重复回复 / 回复自己

- **重复**：跑了两份桥接。桥接有单实例锁（`bridge.lock`），正常会拒绝第二个。
  如果锁文件是崩溃残留的，它会检测 pid 是否还活着然后自动接管。
- **回复自己**：适配器的回声过滤失效了。检查 `_sent` 是不是**在发送之前**写入的。

## 远程操作虚拟机的坑

这些坑在做初始安装时会撞上。

| 现象 | 原因 |
|---|---|
| `VERR_PROC_ELEVATION_REQUIRED` | Guest Control **拒绝**启动需要提权的进程。转手：`Start-Process -Verb RunAs` |
| 提权启动的窗口点不动 | **UIPI**：低权限进程不能往高权限窗口注入输入。让 pyautogui 也提权跑 |
| 提权跑 pyautogui 后它点了自己 | 提权会带一个控制台窗口抢焦点。用 `pythonw.exe` |
| 安装器卡住 2 分钟后自动失败 | UAC 弹窗有超时，没人点就自动否决。**把 UAC 滑块拉到最底** |
| 命令里的引号全乱了 | PowerShell → VBoxManage → 客体 cmd 三层引号。能不用引号就别用，路径别带空格 |
| 客体卡在 `starting` | 你把 Guest Control 自己的 `cmd.exe` 辅助进程杀了。别批量 `taskkill /IM cmd.exe` |

## 还是要人工介入的场合

说清楚，免得你以为这套东西是全自动的：

1. **微信重新登录**：重启虚拟机后腾讯会要求重新登录。点一下按钮 / 扫一次码，之后适配器自动接管。
2. **微信大版本更新**：UIA 热激活靠 `Weixin.dll` 里的固定偏移，更新后大概率失效，要等依赖库跟进。
3. **同一时间只能有一个微信 PC 端在线**：小号在虚拟机里登着，你主机上就用不了。
